# 面积口径说明（作者，2026-11-04）

## 结论
采纳 **SRAM 口径** 对预测器面积进行"存储/逻辑分离"报告，同时如实保留 Yosys 寄存器摊平原始值作为上限。不移动「面积↑≤10%」门槛。

## 依据
1. 文档 §6 明确要求把「触发器/存储面积」与「组合面积」分开统计，且 §0/§3 均将 BHT/BTB 表述为"两个 SRAM 表"。
2. 本环境仅有 Yosys（无 SRAM memory compiler、无 PDK/liberty），Yosys 将 BTB 的 packed 数组摊平为 DFF + 逐 bit 128:1 读 mux，产生 62075 cells——这是**综合产物**，非设计真实代价。任何真实 ASIC/FPGA 流程都会把 7296 bit 的 BTB 做成 SRAM 宏，读解码在宏内部完成。

## 口径分解（实测，来自全核综合）
| 项 | 数值 | 备注 |
|---|---|---|
| 存储位 | BHT 512 + BTB 7296 = **7808 bit** | 生产中以 SRAM 宏实现；本环境无 memory compiler，SRAM 宏面积**未实测** |
| Yosys 寄存器摊平上限 | BASE 43082 → EN1 110036 cells = **+155.41%** | 上限值，如实披露，不冒充达标 |
| 预测控制逻辑（真实增量） | BHT 计数/比较 + BTB tag 比较 + 元数据 FF + 胶水 | 需 memory compiler 才能精确隔离；量级远小于 62075 cells |

## 面积挑战目标判定
- 目标「面积↑≤10%」**口径不变**（不移动门槛）。
- 在 SRAM 口径下，真实增量 = 7808 bit 存储（SRAM 宏）+ 少量控制逻辑；但**无 memory compiler 无法给出最终面积%**，故本项判定为：
  **"寄存器实现原始 +155% 超标；SRAM 实现下预计可显著下降，但无 PDK 实测，维持'未最终定论'"**。
- 不编造 SRAM µm² 或"达标"结论。

## 后续优化项（非本轮返工）
1. BTB 改用 SRAM 宏（需 memory compiler / FPGA BRAM）。
2. 缩小 BTB 表深（128→32/16）与收窄 tag，降低存储与比较逻辑。
3. 为 BTB 增加 `BR_PREDICT_EN` 门控，使禁用开关也能省 BTB 面积（当前只省 BHT）。
